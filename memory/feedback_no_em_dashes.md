# No em dashes (example style rule)

This is an **example** of a personal style preference you can encode in memory. Adapt or
replace it with your own voice rules.

The rule: no em dashes in any authored output — drafts, chat replies, summaries. Use
commas, parentheses, or restructure the sentence instead.

**Scope:** authored content only. Do NOT alter an inbound reply's subject line or quoted
material to strip dashes — a reply subject is inherited, not authored.

**Why:** Consistent voice makes output read as the user's own. Style rules like this are
exactly what belongs in memory: they change HOW you write across every task and live in
no state file.

**How to apply:** Run a quick lint pass on every draft for the style rules in your voice
guide before presenting. Knowing the rule is not enough — check the actual text.
