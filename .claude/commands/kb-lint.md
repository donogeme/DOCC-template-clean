# /kb-lint - KB Manifest Regenerator + Drift Detector

Regenerate the KB manifest at [`ops/_kb/_index.md`](ops/_kb/_index.md) from frontmatter across `ops/_kb/**/*.md`. Detect drift. Triage inbox if requested.

`$ARGUMENTS` accepts optional flags:
- `--check-references` — Also grep the project for legacy `_kb.md` references and report any found.
- `--triage-inbox` — Process [`ops/_kb/_inbox.md`](ops/_kb/_inbox.md) entries and propose target files. (Run during `/weekly`.)
- `--diff` — Generate manifest into a temp string and show diff vs current `_index.md` instead of writing. Used during `/weekly` review.

Default (no flags): regenerate manifest, run drift checks, append findings to `_lint-log.md`.

## Steps

1. **Discover topic files.** Use Glob `ops/_kb/**/*.md`, exclude files starting with `_` (`_index.md`, `_inbox.md`, `_lint-log.md`). The remaining files are topic files under scope subdirectories.

2. **Parse frontmatter from each topic file.** For every topic file:
   - Read the file. Extract the YAML frontmatter block (`---`...`---` at top).
   - Parse using a real YAML parser (Python `yaml.safe_load` via Bash, NOT regex). Required fields: `id`, `scope`, `last_updated`, `summary`. Optional: `related`, `projects`, `keywords`, `people`.
   - If frontmatter parse fails: flag as DRIFT (missing or malformed frontmatter). Continue to next file.
   - Verify `id` matches filename stem (e.g., `acme.md` → `id: acme`).
   - Verify `scope` matches parent directory (e.g., `procurement/acme.md` → `scope: procurement`).

3. **Build manifest data structures.** From parsed frontmatter, build:
   - **All-files table** — sorted by `scope` then `id`. Columns: id | scope | summary | keywords (joined) | last_updated | related (joined).
   - **Lookup by project** — for every distinct value in any file's `projects:` array, list the file ids that reference it.
   - **Lookup by person** — for every distinct value in any file's `people:` array, list the file ids that mention them.
   - **Quick map** — for each scope: file count + concatenated summaries trimmed to one phrase per file (5-7 words).

4. **Drift detection.** Run these checks:
   - **Orphan files** — topic files where no other topic file references them in `related:`. Note: not all files need backlinks (e.g., terminal reference files), but flag for review.
   - **Broken `related:` links** — any `related:` entry that doesn't match a known `id`.
   - **Missing frontmatter** — files missing required fields (`id`, `scope`, `last_updated`, `summary`).
   - **Stale files** — `last_updated` older than the `STALE_THRESHOLD_DAYS` constant in `ops/_kb/_kb-lint.py` (currently a configurable PLACEHOLDER — adjust based on observed usage, do not treat as authoritative).
   - **Mismatched id/filename** — `id:` doesn't match filename stem.
   - **Mismatched scope/directory** — `scope:` doesn't match parent dir.
   - **Cross-scope duplicate detection** — pairs of files in DIFFERENT scopes that share an externally-stable identifier (Gmail thread ID, Notion page UUID, Slack thread timestamp, Google Drive doc ID). Only flagged when the files don't list each other in `related:`. The four pattern definitions live in `DUPLICATE_ID_PATTERNS` in `ops/_kb/_kb-lint.py` — extend or refine there. Same-scope duplications are not flagged (those are normal).
   - **File-count growth** — REMOVED. The original implementation used a fabricated threshold (5 files / 7 days) with no empirical basis. Reintroduce only when actual usage data justifies a specific number.

5. **Generate manifest content.** Write to `ops/_kb/_index.md` with this structure:

   ```markdown
   # KB Manifest

   > **Auto-generated by `/kb-lint`. Do not edit by hand.**
   > Last regen: YYYY-MM-DD HH:MM ET
   > Topic files: N | Scopes: 10 | Last drift check: clean / N issues

   ## Quick Map

   | Scope | Files | Purpose |
   |-------|-------|---------|
   | procurement | N | (concatenated 5-7-word phrases per file) |
   | ... |

   ## All Files

   | ID | Scope | Summary | Keywords | Updated | Related |
   |----|-------|---------|----------|---------|---------|
   | (rows sorted by scope, then id) |

   ## Lookup By Project

   | Project | Relevant KB Files |
   |---------|-------------------|
   | (sorted alphabetically) |

   ## Lookup By Person

   | Person | Mentioned In |
   |--------|--------------|
   | (sorted alphabetically by name) |

   ## Drift Report (last run YYYY-MM-DD HH:MM ET)

   - Orphans: [list or "none"]
   - Broken related: [list or "none"]
   - Missing frontmatter: [list or "none"]
   - Stale files (>90d): [list or "none"]
   - File-count growth: N (was M as of [date])

   For full history, see [`_lint-log.md`](_lint-log.md).
   ```

6. **Determinism rule.** ALL sorting must be stable and explicit. ALL timestamps must be the run-start timestamp (single source). Re-running `/kb-lint` on unchanged corpus must produce byte-identical `_index.md`. The ONLY non-deterministic field is the "Last regen" timestamp at the top — make this configurable; default to current time but accept `--frozen-timestamp <ISO>` for testing.

7. **Append entry to `_lint-log.md`.** New entry at TOP (newest first):

   ```markdown
   ## YYYY-MM-DD HH:MM ET — /kb-lint regen

   - **Trigger:** manual / weekly / migration
   - **Files scanned:** N topic files across 10 scopes
   - **Drift flagged:** [count by category, or "clean"]
   - **Manifest regen:** wrote `_index.md` (Y bytes, Z lines)
   - **File-count change:** N (delta from last run: +K / unchanged)
   - **Notes:** [anything specific]
   ```

8. **If `--check-references` flag set:** Run `Grep` for `_kb.md` across the entire project (excluding `ops/_kb.md` itself, `ops/_kb-migration.md`, `_session-log.md`, archived files). Report all matches as legacy reference candidates. After cutover (Session 10), this should return zero. During migration, expect references in CLAUDE.md, .claude/rules/ops.md, and command files until they're updated.

9. **If `--triage-inbox` flag set:** Read `ops/_kb/_inbox.md`. For each entry:
   - Identify keywords and people
   - Match against existing topic files (via manifest lookup tables)
   - Propose top 1-2 target files
   - Output a triage list for [YOUR NAME]'s confirmation. Do NOT auto-merge — that's [YOUR NAME]'s call during `/weekly`.

10. **If `--diff` flag set:** Generate the manifest content as a string. Compute diff vs current `_index.md`. Show diff (added/removed/changed lines), don't write. Useful during `/weekly` to see what changed.

## Implementation Notes (for the executing agent)

- **Use Bash + Python** for the parse + generation. YAML parsing in Python is reliable; markdown table generation is straightforward. Do not attempt this in pure markdown reasoning — fragility is too high.
- **Single Bash invocation** for the whole linter where possible. Reduces tool calls and ensures atomic regen.
- **Read the corpus once.** Don't re-Read individual files multiple times within a single lint run.
- **Sort everything.** Python `sorted()` with explicit keys. Tables sorted by primary key, then secondary.
- **Format dates as ISO 8601** (`YYYY-MM-DD`). Always.
- **Keywords/related/people in tables:** join with `, ` (comma + space), sorted alphabetically.
- **Manifest does NOT contain content from topic files.** Only metadata. Manifest stays small and fast to load.

## Output to user

After running, report:

```
/kb-lint complete

Topic files: N (delta: +K)
Manifest regenerated: Y bytes
Drift: clean / N issues — see _lint-log.md

Lookup tables:
- N projects mapped
- N people mapped
- 10 scopes covered
```

If drift found, list the top 3 issues inline with file paths so [YOUR NAME] can act.

## Hard Rules

- **Never edit topic files** during a lint run. Read-only on topic files.
- **Always preserve manifest determinism.** If a non-deterministic source slips in (random ordering, time-based hash), fix it before next run.
- **YAML parse failure = DRIFT, not crash.** Report the file, continue with the rest.
- **Never skip drift checks** to make output look clean. Always run all checks.
- **Wikilinks in topic files** (`[[scope/file]]` syntax) are NOT validated by /kb-lint v1. Future enhancement: parse and verify them. For now, the `related:` frontmatter is the single source of truth for cross-file linking.
